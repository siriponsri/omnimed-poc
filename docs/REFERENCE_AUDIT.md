## ข้อสรุปด้าน compatibility

1. Reference healthcare ทั้งสี่ไม่ใช่ dependencies ของ OmniMed: Python/FastAPI, PostgreSQL และ Next.js ยังตรง target stack และ M0 ไม่มี clinical feature ที่แอบยกเข้ามา
2. Role inheritance หรือ claim ว่าระบบ reference รองรับมาตรฐาน ไม่ได้พิสูจน์ Finance boundary ของ OmniMed ต้องทดสอบ authorization/projection ของตนเองเมื่อเริ่ม protected routes
3. HAPI เป็น reference implementation ส่วน supported FHIR R4 subset ต้องระบุ field/operation และ validation evidence ของ OmniMed เอง; mapping document ไม่ใช่ผ่าน conformance test
4. Skills/plugins และ model provider ต้องอยู่ใน developer tooling Product ต้อง start/test ได้โดยไม่ติดตั้งหรือเรียกส่วนเหล่านี้
5. รายงานนี้บันทึกการศึกษาและ license evidence เท่านั้น การอนุญาตคัดลอก code ในอนาคตต้องตรวจ license ของไฟล์/version ที่จะใช้ พร้อม provenance และตรวจความเข้ากันกับ SRS ตาม master §15

## Retrieval limitations ที่บันทึกไว้

- บาง raw.githubusercontent.com URL อ่านไม่สำเร็จ จึงใช้หน้า GitHub ของไฟล์เดียวกันเมื่ออ่านได้ ไม่ถือ fetch error ว่า repository ถูกลบ
- [OpenELIS docs entrypoint](https://docs.openelis-global.org/) redirect ไป Atlassian แต่คืนเนื้อหา 0 บรรทัด จึงไม่อ้างว่าอ่าน user manual หรือ permission matrix สำเร็จ ใช้ current official capabilities page และ README สำหรับ comparative study แทน
- URL OpenELIS เดิมของ master ยังคงอยู่ใน register; การเพิ่ม current repo เป็นการติดตาม source drift ไม่ใช่แก้ authoritative SRS
- ไม่ได้รันตัวอย่าง OpenRouter/Agents SDK/OpenHands/CrewAI, ไม่ได้ติดตั้ง Hallmark/No AI Slop และไม่ได้รับรองผล benchmark/security/compliance ที่เจ้าของ reference โฆษณา
