# Proposed POC assumptions for contract freeze

These are proposed reductions/interpretations for the root orchestrator to accept and record in the frozen POC contract. They are not edits to the supplied SRS. Identifiers POC-A## are local assumption IDs, never SRS requirement IDs.

| Local assumption | Decision | Meaning |
|---|---|---|
| POC-A01 | M0-only delivery | Master §20 is definitive. Foundation seed contains tenant/config/role metadata only. M1–M5 demo patient, encounters and clinical behaviors remain future tasks. |
| POC-A02 | Synthetic adult identity | Future fixture: adult human Somchai Demo, Party linked to Patient, explicit self relation and system-generated HN. No real Thai citizen number, guardian, animal, phone/address or smart-card data. |
| POC-A03 | Single tenant and no production RLS claim | One fixed synthetic tenant; tenant_id is mandatory on all future patient tables. Local application authorization is a limited POC mechanism. Production RLS, encryption, retention, IAM and cross-tenant service remain deferred. |
| POC-A04 | OPD encounter state ownership | PAT-02 owns start, although persistence lands in M1: AMB/planned then in_progress at first doctor call. Preserve patient linkage, visit number and status history; no IPD class transitions. |
| POC-A05 | Observations and allergy status | BP is parent with systolic/diastolic children. Temperature, weight and Hb are coded/unit-bearing Observations with effective time, actor and reference snapshots. Allergy unknown is distinct from no-known-allergy; manual confirmation can be selected without introducing CDS. |
| POC-A06 | Order state interpretation pending ADR | Before M3 choose immutable clinical payload plus allowed lifecycle status updates with append-only history, or immutable event-derived status. Every revision/discontinuation has a linked new row. Never claim literal no-row-UPDATE alongside a revoked predecessor mutation without this ADR. |
| POC-A07 | Lab performed/released separation | Minimal synthetic sample/sample_item/analysis/result trace is retained for M4. technical_complete causes one clinical fulfillment charge; released causes Observation publication. CBC demo contains only Hb and is visibly labeled Hb-only. |
| POC-A08 | One lab operator exception | Use only the master R-LAB role in the demo. Any entry+release by the same user is an explicit single-operator synthetic tenant option, permitted by the exception in US-ANC01-05; no production dual-validation or QC claim. |
| POC-A09 | Restricted medication demo | Paracetamol 500 mg is a fixed synthetic adult catalog example, not a dosage recommendation. Typed fields, positive dose/quantity, allowed route, active order and remaining quantity are validated. No pediatric, renal, interaction, allergy decision engine, controlled substance or real stock function. |
| POC-A10 | Demo billing definitions | Only fixed synthetic self-pay/default THB price definitions. Price is snapshotted at event time; catalog items have inventory_item_id null. Billing label avoids clinical detail; no real tariffs, eligibility, tax invoice, payment callback or accounting posting. |
| POC-A11 | Completion remains gated | Before M5 decide minimum synthetic signed note/principal diagnosis and account settlement semantics required for completed. Until then, no fake completion endpoint, no automatic assumption that charged means paid. |
| POC-A12 | Reference-only transactional events | Existing SRS event names only; event_id UUID, tenant/time/context and reference IDs, domain change and outbox in one transaction, consumer idempotency. No broker/cloud/external dispatcher needed. Full event catalog and replay operations are outside M0. |
| POC-A13 | Seven exact roles and deny precedence | R-REG/R-SCR/R-DOC/R-LAB/R-PHA/R-FIN/R-ADMIN only. R-ADM is not R-ADMIN. Support roles cannot inherit clinical read access by adding a clinical role; root policy must test this precedence when RBAC is implemented. |
| POC-A14 | FHIR boundary | R4 (4.0.1) adapter mapping only in M0. Minimal local export of selected resources in M5; internal statuses must be explicitly mapped to valid FHIR codes. No inbound writes, full server, SMART, TH Core certification, R5 adapter or government integration. |
| POC-A15 | Source provenance | Missing ai-agent-routing.zip is documented. Control-plane four-role documents derive from the supplied master/HANDOFF, not inspected course code. Missing legacy ADR/schema/Next Account documents do not prevent M0 but gate integration-specific future choices. |
| POC-A16 | Reference UI only | Retain dense Thai clinical worklists, consistent patient header and role navigation. Do not transplant mockup fake KPIs, pediatric dosing advice, placeholder standard codes or semantically conflicting lab charge labels. |
